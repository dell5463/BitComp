# Training modes (GPU PC, bit_plane_rowcol, train_size 1,024, 64,000 steps, CUDA) — decision

Tables: `SUMMARY.md` (generated by `scripts/summarize.py compare|rate|paired|matched`).
Sample: 200 validation images (development scale), one training seed per variant.

**Winner: teacher_forcing** -> base for `configs/objectives.json`.

Primary evidence: rate at acceptable quality (bpp for pooled PSNR >= 20/25/30/35 dB, paired
image bootstrap vs teacher_forcing; negative = fewer bits):

- rollout: raw -0.14 / +0.15 / +0.39 / +0.30 bpp; range-coded -0.04 / +0.11 / +0.16 / +0.18.
  Better only at 20 dB; significantly worse at 25-35 dB (all CIs exclude 0).
- scheduled: raw -0.04 / -0.03 / +0.04 / -0.07 (a near tie, mostly not significant);
  range-coded +0.01 / +0.06 / +0.09 / +0.10 (significantly worse at 25-35 dB).

Thresholds 0.60-0.85 at matched complete-file bpp (requested focus): scheduled +0.43 dB mean,
rollout -0.29 dB mean vs teacher_forcing. Rollout gains +0.86 / +1.35 dB at t = 0.80 / 0.85, but
every point in this range is 8.6-15 dB PSNR, below any usable quality, so the gain does not
change the decision.

Per-threshold behaviour: rollout makes fewer wrong omissions at a given threshold (higher PSNR per
threshold, e.g. t = 0.95: 29.35 dB vs 22.06 dB) but transmits more bits (7.38 vs 6.41 bpp); at
matched rate in the 25-35 dB range teacher forcing is cheaper.

The envelope-mean metric favours scheduled (+1.64 dB raw, CI [+1.42, +1.91]) almost entirely
because of t = 0.5-0.6 (12 dB vs 5 dB output); see `results/position_ablation/DECISION.md` for why
that metric is not used for decisions.

Confound (limitation): checkpoints are selected by teacher-forced validation BCE. For scheduled
this picked step 16,000, when only 4% of inputs had been replaced (the schedule reaches 50% at
60% of training), so the swept scheduled model is close to a teacher-forced one. Rollout's best
checkpoint was step 56,000 (32% replaced). Selecting reconstructed-context checkpoints by a
codec-aware validation criterion is NOT YET MEASURED.

Reproducibility: teacher_forcing is config-identical to position_ablation/bit_plane_rowcol; its
history and all 2,800 sweep rows are identical to that run.
Cost: scheduled 30,786 s and rollout 32,350 s of training (2 concurrent GPU jobs) vs 945 s for
teacher forcing.

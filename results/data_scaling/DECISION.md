# Data scaling (GPU PC, 64,000 steps, CUDA) — decision

Tables: `SUMMARY.md` (generated by `scripts/summarize.py compare|paired|matched`).
Sample: 200 validation images (development scale), one training seed per size.

**Winner: n01024 (train_size 1,024)** -> base for `configs/position_ablation.json`.

Evidence (raw-payload complete-file operational RD, paired image bootstrap, 1,000 resamples):

- n01024 beats every other size: vs n45000 +0.45 dB (95% CI of n45000 - n01024: [-0.67, -0.11]),
  vs n00256 +0.28 dB ([-0.49, -0.06]), vs n00032 +1.40 dB, vs n05000 +1.90 dB.
- Range-coded payload: n01024 and n45000 tie (-0.02 dB, CI [-0.12, +0.06]); both beat the rest.

Does more data improve complete-file RD? **Not monotonically at this budget.** Ranking (raw):
n01024 > n45000 > n00256 > n00032 > n05000. n00032 clearly overfits (val BCE best at step
8,000, then 0.54 -> 2.66). n05000 ranks last although it sits between two better sizes, which
indicates run-to-run training variance (constant LR 1e-3, noisy validation checkpoints, single
seed) of the same order as the data effect. The image bootstrap does not capture that
variance. Seed replicates are NOT YET MEASURED (the CLI ties the init seed to the split seed,
so replicates need a separate init-seed option first).

Re-check with rate at acceptable quality (added at the position stage; bpp needed for pooled
PSNR >= 20/25/30/35 dB, paired bootstrap vs n01024): n45000 needs more bits at every target
(raw +0.08 / +0.41 / +0.14 / +0.06 bpp; range-coded +0.02 / +0.03 / +0.04 / +0.05, CIs exclude 0
except range-coded 20 dB). n00256 is cheaper at 20 dB raw (-0.31 bpp) but ties at 25-30 dB raw
and costs +0.08 to +0.14 bpp with range-coded payloads. n00032 and n05000 are worse everywhere.
**The decision stands: n01024.**

Absolute RD is poor for every size: at 0.3-6 bpp pooled PSNR is 7-16 dB (useless quality);
only thresholds 0.975-0.99 reach 25-38 dB, at 7.2-8.0 bpp. Curves are non-monotone in the
threshold (cascading errors after wrong omitted MSBs).
